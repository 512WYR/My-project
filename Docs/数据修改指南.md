# 数据修改指南

本文说明在项目里调整角色、技能、敌人、编队和全局规则时，应该改哪些文件、用什么方式改，以及哪些内容仍然必须改 C#。

## 一、结论

- **绝大多数平衡数值都在 Unity 的 ScriptableObject 资产里**，可以直接在 Inspector 修改，不需要改 C#。
- **战斗、地图、缩放、肢体规则**集中在 `GameCatalog.asset`。
- **英雄技能**是独立技能资产；**怪物技能**内嵌在怪物角色资产里。
- **事件、消耗品、饰品、义肢、伤害/命中公式**仍写在 C# 里。
- **预制体只负责 UI 表现**，不承载战斗数值。

## 二、数据加载关系

```text
GameCatalog.asset
├─ Heroes[]                 → CharacterDefinition（英雄）
│                              ├─ BasicSkills[]      → SkillDefinition（技能资产）
│                              ├─ PrimalSkills[]     → SkillDefinition
│                              └─ TechnicalSpecial   → SkillDefinition
├─ Enemies[]                → 旧的三个脚本敌人（未生成编队时的兜底）
├─ Monsters[]               → 设计怪物与 Boss
│                              └─ EnemySkills[]      → 内嵌 SkillSpec（不是独立资产）
├─ NormalEncounters[]       → 普通战编队
├─ EliteEncounters[]        → 精英战编队
└─ BossEncounters[]         → Boss 战编队
```

运行时的读取顺序：

1. `StageOneApp` 优先使用场景里拖入的 `Catalog`。
2. 场景字段为空时，从 `Resources/StageOne/GameCatalog` 加载。
3. `CharacterDefinition.ToSpec()` 把资产转换成运行时 `ActorSpec`。
4. `GameCatalog.Rules()` 和 `MapRules()` 把全局数值转换成 `CombatRules` / `MapRules`。

因此改资产不需要重新编译，也不需要重新生成场景。

## 三、资产目录

根目录：`Assets/StageOne/Resources/StageOne/`

| 内容 | 位置 |

### 3.1 英雄

四个英雄：

| 角色 | 资产 |
| --- | --- |
| 盾卫 | `Characters/shield.asset` |
| 战士 | `Characters/warrior.asset` |
| 奶妈 | `Characters/medic.asset` |
| 枪手 | `Characters/gunner.asset` |

英雄和怪物共用 `CharacterDefinition`，但每个资产顶部有 `Kind` 字段决定 Inspector 显示哪一半：

- `Hero`：只显示通用 + 英雄专用字段。
- `Monster`：只显示通用 + 怪物专用字段。
- `Unset`：旧资产尚未迁移，显示全部字段并给出警告。

旧资产先运行一次菜单 `GameMake/Assign Character Kinds`（`GameMake/Prepare Stage One` 也会自动执行）。迁移只写 `Kind`，不改其他字段。

可改字段：

| 字段 | 含义 |
| --- | --- |
| `Kind` | `Hero`；决定 Inspector 分区与 `ToSpec()` 的字段收敛 |
| `MaxHp` | 最大生命 |
| `Speed` | 行动顺序速度 |
| `Attack` | 攻击力，技能伤害按它计算 |
| `Accuracy` | 基础命中 |
| `CritChance` | 暴击率 |
| `Dodge` / `Defense` | 闪避率 / 防御 |
| `SanityOffset` | 初始理智偏移 |
| `BasicSkills` | 普通形态技能列表 |
| `PrimalSkills` | 低理智形态技能列表 |
| `TechnicalSpecial` | 高理智形态额外技能（与 `BasicSkills` 合并） |
| `Silhouette` | 界面剪影键，不要随意改 |

### 3.2 英雄技能

`Skills/` 下按角色前缀命名：

- 战士：`w_*`
- 盾卫：`s_*`
- 枪手：`g_*`
- 奶妈：`m_*`

每个技能资产只有一个 `Spec` 字段，展开后是 `SkillSpec`。

常用字段：

| 字段 | 含义 |
| --- | --- |
| `Name` / `Description` | 界面显示名称与描述；描述第一行是站位/目标符号，第二行是效果 |
| `Effect` | `Attack` / `Heal` / `Protect` / `Buff` / `Sanity` |
| `Target` | `Enemy` / `Ally` |
| `Multiplier` | 伤害或治疗倍率，数值 = `Attack × Multiplier` |
| `ActorRanks` | 施放站位掩码 |
| `TargetRanks` | 合法目标站位掩码 |
| `Uses` | 每场次数；`0` = 不限次 |
| `Accuracy` | 技能命中；以 `0.9` 为基准，和角色命中相加 |
| `Targeting` | `Choose` = 玩家选目标；`All` = 全队/群体，不需要点击目标 |
| `Area` | `Single` / `Adjacent` / `Splash` / `Pierce` / `Party` |
| `AreaMax` / `AreaRatio` / `AreaDecay` | 扩散、溅射、贯穿的范围与衰减 |
| `Bleed` / `BleedTurns` / `BleedChance` | 流血伤害、持续次数、施加概率 |
| `Imbalance` | 失衡：跳过下一次行动，并让位移技在2回合内必定命中 |
| `Interrupt` | 打断下一次行动 |
| `Cleanse` | 清除减益 |
| `PullToFront` / `PullChance` | 拖拽到敌方 1 号位及概率 |
| `SelfMove` | 施放后自身前后移动 |
| `Grant` / `SelfGrant` / `GrantDefense` / `GrantAccuracy` | 给全队或自身施加的增益 |
| `Rider` | 附加效果（吸血、恢复理智） |
| `RandomTarget` | 是否随机选目标 |

**站位/目标掩码是位掩码**：

| 位置 | 位 | 十进制 |
| --- | --- | --- |
| 1 号位 | bit 0 | `1` |
| 2 号位 | bit 1 | `2` |
| 3 号位 | bit 2 | `4` |
| 4 号位 | bit 3 | `8` |

例如：

- `15` = 1~4 号位全部合法。
- `12` = 只能站/打 3、4 号位。
- `3` = 只能站/打 1、2 号位。
- `14` = 2、3、4 号位。

### 3.3 怪物与 Boss

位置：`Characters/`

| 怪物 | 资产 |
| --- | --- |
| 小怪 1 / 小怪 2 | `minion1.asset` / `minion2.asset` |
| 理智怪 / 精英理智怪 | `sanity.asset` / `elite_sanity.asset` |
| 流血怪 / 精英流血怪 | `bleed.asset` / `elite_bleed.asset` |
| 高伤怪 / 精英高伤怪 | `high.asset` / `elite_high.asset` |
| 肉盾怪 / 精英肉盾怪 | `tank.asset` / `elite_tank.asset` |
| 回血怪 | `healer.asset` |
| 复制首领 | `copy_boss.asset` |
| 巨型首领 | `giant_boss.asset` |
| 组合首领部件 | `random_summoner.asset` / `steam_machine.asset` / `operator.asset` |

除了和英雄相同的 `MaxHp` / `Speed` / `Attack` / `Accuracy` / `CritChance` / `Dodge` / `Defense`，怪物还有：

| 字段 | 含义 |
| --- | --- |
| `Kind` | 应为 `Monster`；Inspector 只显示通用 + 怪物字段 |
| `Behavior` | AI 类型：`Simple` / `Sanity` / `Bleed` / `HighDamage` / `Tank` / `Healer` / `CopyBoss` / `GiantBoss` / `RandomSummoner` / `SteamMachine` / `Operator` |
| `EnemySkills` | 内嵌技能数组；改了立即影响该怪物 |
| `RankWidth` | 占几个站位（1～4）；大于 1 时战斗 HUD 会把卡片拉宽覆盖后续卡位，且不会自动前移 |
| `Immobile` | 固定在原地，免疫拖拽、不参与站位补位 |
| `ActionInterval` / `ActionPhase` | 每几回合行动一次 / 首次行动相位 |
| `BossHealOnHeroDeath` | 英雄死亡时 Boss 回复量 |
| `GuardReduction` | 守护挡刀减伤 |
| `SummonPool` | 随机召唤怪可变成的怪物池 |

> 怪物技能不是独立资产，直接展开怪物资产里的 `EnemySkills` 修改。

> 怪物没有理智，也没有部位。`SanityOffset`、`BasicSkills`、`PrimalSkills`、`TechnicalSpecial` 只属于英雄；怪物资产即使残留这些值，`ToSpec()` 也会忽略，运行时敌人理智恒为 0。战斗只给英雄创建部位，且 `LimbSystem.Damage()` 拒绝一切非 Player 单位，所以**所有怪物都不会重伤或断肢**；怪物模板里没有、也不应该有部位字段。

#### 角色与怪物立绘

立绘不挂在资产上，而是按**角色 Id** 从 Resources 自动查找：

1. 怪物图片放到 `Assets/StageOne/Resources/StageOne/EnemyArt/`。
2. 英雄图片放到 `Assets/StageOne/Resources/StageOne/HeroArt/`，文件名用英雄 Id：`warrior` / `shield` / `gunner` / `medic`。
3. 文件名必须与 `Characters/` 下的资产 Id 一致，例如 `minion1.png`、`elite_tank.png`。
4. 不需要改 `GameCatalog` 或任何 `.asset`；重新进入战斗后，战斗卡片会优先显示立绘。
5. 没有对应文件的单位（目前是 `copy_boss`、`giant_boss`、`steam_machine`、`operator`、`random_summoner`，以及全部英雄）继续使用程序化剪影，不会报错。
6. 立绘按原始宽高比等比缩放并居中放入卡片立绘区域；死亡时整张图变灰。图片导入类型保持默认即可（`Texture2D` 能被 `Resources.Load<Texture2D>` 读取），建议开启 Alpha Is Transparency 以保留透明边缘。
7. 战斗卡片没有底色边框：立绘/剪影直接站在站位轨道上，只有可行动、可选或正在查看时才会出现半透明底色和角标。立绘区域为 `156×136`（卡片 `160×220`），现有 2:3 图片会显示为约 `91×136`。
8. 布局改动写在 `ModularHudBuilder` 里，需要在 Unity 执行 `GameMake/Gothic HUD/Rebuild Modular HUD` 重新生成场景与预制体后才会生效。

现有文件对应关系：`小怪1/2 → minion1/minion2`、`理智怪 → sanity`、`精英理智怪 → elite_sanity`、`流血怪 → bleed`、`精英流血怪 → elite_bleed`、`高伤怪 → high`、`精英高伤怪 → elite_high`、`肉盾怪 → tank`、`精英肉盾怪 → elite_tank`、`回血怪 → healer`。

### 3.4 敌人编队

选中 `GameCatalog.asset`，在 Inspector 找到：

- `NormalEncounters`：普通战
- `EliteEncounters`：精英战
- `BossEncounters`：Boss 战

每个编队有 4 个 `Slots`，下标 `0~3` 对应敌方 1~4 号位：

- 拖入 `CharacterDefinition` 资产表示该位置放这个单位。
- `None` 表示空位。
- 多格怪物（`RankWidth > 1`）只在它起始的那个槽位填一次，后续槽位保持 `None`；战斗占位与 HUD 跨卡都由 `RankWidth` 自动处理。
- Boss 房里每个单位名会自动加“首领·”前缀。
- 战斗时从对应表中随机抽一个编队。
- 如果编队表为空，会回退到 `GameCatalog.Enemies` 里的旧三个敌人。

## 四、修改步骤

1. 在 Unity 的 Project 窗口定位到对应 `.asset`。
2. 选中后在 Inspector 修改数值。
3. `Ctrl+S` 保存项目。
4. 进入 Play Mode 验证。
5. 需要对比时，用 Battle Lab 复现同一场战斗。

修改技能描述时：

- 第一行保留站位/目标符号，例如 `○○●●/○○●●`。
- 第二行写效果，避免太长导致按钮放不下。
- 百分比与预计点数分开写，例如“造成攻击力75%的伤害，预计8点”。

事件池有两个不在 Inspector 里的规则：

- `EventScripts.Catalog` 中 `Healing = true` 的内容（目前是 EVT-005、EVT-006）只有在 `RunState.Battles >= 1` 后才进入事件池。
- 正常抽取会参考 `MapState.EventHistory`：优先未出现的事件，池耗尽后选最久未见。历史是 `List<string>`，按进房顺序追加；新增回血事件时记得加 `Healing` 标记。

### 5.1 事件与祭坛的选项

全部事件与祭坛都写在 [EventScripts.cs](../Assets/StageOne/Core/EventScripts.cs)，没有 `.asset` 资产。一个事件由三部分组成：

1. `Catalog` 数组里的一条登记（`Id`、`Title`、`Kind`、`Gate`、`Healing`）。
2. `Page()` 的 `switch` 里对应的方法，负责生成当前这一步的正文与选项。
3. 如果事件会进入战斗，`ResolveBattleReturn()` 里对应的胜利奖励分支。

**改一个选项**：找到该事件方法里对应的 `page.Choices.Add(new EventChoice(...))`。参数依次是按钮标题、按钮下方的小字说明、选项执行体：

```csharp
page.Choices.Add(new EventChoice(
    "继续挖矿",
    "全队理智 -3 · 矿石 +4 · 剩余 " + (left - 1) + " 次",
    s =>
    {
        s.TeamSanity(-3);
        s.GainSupplies(4, "矿石");
        s.Node.EventCount++;
        s.End("你带着矿石退了出来。");       // 结束整个事件
        // 或者 s.GoTo(1, "进入下一步");     // 跳到下一步
    }));
```

- **只显示在特定条件**：`new EventChoice(...) { Shown = 条件 }`。隐藏的选项不显示，但仍占数组下标。
- **显示但不可点**：`{ Enabled = 条件 }`。
- **多步事件**：用 `s.GoTo(step, note)` 推进，用 `node.EventStep` 判断当前步；中间状态存在 `node.EventFlag`、`EventCount`、`EventLimit`、`EventTarget` 上。
- **选项按当前 `page.Choices` 的下标执行**，不要依赖固定编号；`EventFlag` 是给“下一步”读的标记，不是选项下标。

常用的选项效果（`EventSession` 上的方法）：

| 写法 | 效果 |
| --- | --- |
| `s.GainSupplies(4, "矿石")` | 补给/矿石 +4，并把结果写进本次说明 |
| `s.TeamSanity(-3)` | 全队存活队员理智 -3 |
| `s.Run.PlayerSanity = ...` | 直接改玩家理智（记得用 `SanityProbability.Clamp`） |
| `s.HealHero(hero, 40)` | 该队员恢复 40% 最大生命 |
| `s.DamageHero(hero, 30)` | 该队员失去 30% 最大生命，最低留 1 点 |
| `s.GrantProsthetic()` | 发一件随机义肢，返回该物品 |
| `s.GrantAccessory()` | 发一件随机饰品，返回该物品 |
| `s.RequestBattle(NodeType.Battle, "提示")` | 关闭事件页并进入战斗；用 `EliteBattle` 可打精英战 |
| `s.ShuffleRanks()` | 打乱全队站位 |
| `s.End("结算文字")` / `s.GoTo(1, "文字")` | 结束事件 / 进入下一步 |

注意：`Page()` 每次重绘都会调用，**不能在里面抽随机数或改状态**；随机数放在 `Roll()`（进房时）或选项执行体里。

**祭坛（EVT-008）**是这条规则的典型：两项随机报价在 `Roll()` 调用的 `RollAltar()` 里抽定，分别存进
`NodeState.AltarResourceForSanity` 与 `AltarSanityForResource`。`AltarOffer` 记录资源种类、数量、
理智接收/支付方与要交割的义体；`Workshop()` 只把报价渲染成「献上资源」「献上理智」两项。

- **改汇率**：`EventScripts.AltarSanityPerSupply`（4）、`AltarSanityPerHealth`（1）、
  `AltarSanityPerProsthetic`（16）三个常量即可整体调价。
- **改随机区间**：补给数量在 `RollResourceForSanity()` / `RollSanityForResource()` 里写死为 2–4；
  生命报价是最大生命的 10%–25%，且至少留 1 HP。
- **新增资源种类**：同时改 `MapModel.AltarResource` 枚举、两个 `Roll*` 方法、`Describe*Trade()`
  的按钮文案与两个 `Trade*` 的结算分支，漏掉任何一处都会让报价显示或结算对不上。

**改事件奖励**：分两种。

- **选项立即结算**：直接写在选项的 `Run` 里（上面的 `GainSupplies`、`GrantAccessory` 等）。
- **战斗胜利后结算**：写在 `ResolveBattleReturn()` 的 `switch` 里。这里只在胜利时调用一次，撤退不发奖励；文本和奖励要一起改，避免“说明里写了饰品但实际没发”。

例如给 EVT-001 的战斗胜利加一件饰品：

```csharp
case "EVT-001":
    run.Map.Supplies += 2;
    NameAccessory(run);                       // 抽一件饰品并放进队伍仓库
    return "矿道深处的响动终于停了。补给 +2，并获得一件饰品。";
```

**新增一个事件**：

1. 在 `Catalog` 里加一条：`new Script { Id = "EVT-009", Title = "标题", Kind = NodeType.Event }`。
   - `Kind = NodeType.Altar` 会进祭坛池，否则进事件池。
   - `Gate = Gate.High` / `Gate.Low` 控制只在玩家理智 ≥50 / <50 时出现。
   - 回血类事件加 `Healing = true`，保证队伍至少打过一场后才出现。
   - `Weight` 字段目前没有参与抽取：抽取优先未出现的内容，池耗尽后选最久未出现的一条。
2. 在 `Page()` 的 `switch` 里加 `case "EVT-009": ...; break;`，并实现对应方法。
3. 如果有战斗，在 `ResolveBattleReturn()` 里加 `case "EVT-009"`，写清胜利奖励。

### 5.2 宝箱房的奖励

宝箱房的逻辑在 [StageOneApp.cs](../Assets/MainGame/Runtime/StageOneApp.cs) 的 `EnterTreasureRoom()`。当前行为是**每个宝箱发一件随机饰品**，用 `ActiveNode.EventFlag` 记录“已经开过”，重进不会重复发。

- **改饰品池**：改 [AccessorySystem.cs](../Assets/StageOne/Core/AccessorySystem.cs) 的 `Defaults` 数组；`Drop()` 从这里等概率抽一件。
- **改发放数量或类型**：直接改 `EnterTreasureRoom()`，例如：

```csharp
// 两件饰品
Run.AccessoryStock.Add(Encounter.DropAccessory(Run.Random));
Run.AccessoryStock.Add(Encounter.DropAccessory(Run.Random));

// 改成补给或义肢
Run.Map.Supplies += 6;
Run.Prosthetics.Add(Encounter.DropProsthetic(null, Run.Random));

// 改成消耗品
Run.Consumables.Add(ConsumableSystem.Clone(ConsumableSystem.Find("con_hp_restore")));
```

- 无论发什么，结算完后都要保持 `ActiveNode.EventFlag = 1`，否则再次打开页面会重复发。
- 改完行为后同步页面文案：[RoomPages.cs](../Assets/MainGame/Runtime/RoomPages.cs) 的 `Treasure()`。

### 5.3 补给站的选项

补给站当前有四项操作，入口都在 [StageOneApp.cs](../Assets/MainGame/Runtime/StageOneApp.cs) 与 [RoomPages.cs](../Assets/MainGame/Runtime/RoomPages.cs)：

| 操作 | 方法 | 规则 / 可调数值 |
| --- | --- | --- |
| 治疗全队 | `SupplyHeal()` | 每名存活队员恢复 `GameCatalog.SupplyHealRatio`（默认 35%）；每间补给站一次 |
| 静养 | `SupplyCalm()` | 玩家理智 +`Exploration.CalmSanity`（默认 10）；每间一次 |

| 商店 | `OpenSupplyShop()` / `BuySupplyShopItem()` | 规则在 `SupplyShop`；消耗 `Run.Map.Supplies`，商品与价格见 `SupplyShop` |

“每间一次”由 `Run.Map.SupplyHealed` / `SupplyCalmed` 控制，`EnterSupplyRoom()` 每次进房会重置。想加一项新服务：

1. 在 `MapModel.cs` 的 `MapState` 上加一个 `bool SupplyXxx` 标记（若每间限一次）。
2. 在 `StageOneApp` 里写对应方法，并在 `EnterSupplyRoom()` 里重置标记。
3. 在 `RoomPages.SupplyMain()` 的 `Choices` 和 `Choose` 里加一项。

供给与价格集中在 `SupplyShop`：商店购买会先扣 `Run.Map.Supplies` 再发放副本；治疗、静养、修复与安装仍然免费。

## 七、Battle Lab 调参与固化

Battle Lab 的数值：

- 只存在于当前运行配置和导出的 JSON 中。
- **不会自动写回** `GameCatalog.asset`、角色资产或技能资产。
- “保存配置文件”导出到 `Application.persistentDataPath/BattleLab/`。
- 导入 JSON 也只在 Battle Lab 内生效。

要把调试结果固化进游戏，有两条路：

1. **手动抄写**：按本文第三节找到对应资产，把数值填进 Inspector。
2. **批量写回工具**：可以新增一个编辑器工具，读取 Battle Lab JSON 并写入对应资产。目前仓库里还没有这个工具。

## 八、注意事项

1. **不要删除资产来“重置”**：删除后重新运行 `GameMake/Prepare Stage One` 会按代码里的初始值重新创建，之前的调整会丢失。
2. **`Prepare Stage One` 不会覆盖已有资产**：生成器里的 `Asset<T>` 在资产存在时直接返回，保留手改数据。
3. **新增 C# 字段时旧资产读不到值**：已有 `.asset` 不会自动获得新字段，通常会读成 `0` / `false`。需要迁移代码或手动补值；`GameCatalog.Migrate` 只处理了部分字段。
4. **英雄技能是共享引用**：多个角色引用同一个技能资产时，改一处会影响所有引用者。
5. **怪物技能内嵌**：改怪物技能只影响该怪物，不会影响英雄技能。
6. **Play Mode 改资产也会保留**：ScriptableObject 的修改不像场景对象那样在退出时回滚；但仍建议在退出 Play 后确认并保存。
7. **技能次数与描述要同步**：改了 `Uses`、倍率、概率后，记得同步 `Description`，否则界面显示与实际效果不一致。
8. **测试用临时值**：像拖拽概率这类临时调高的数值，验证完成后要记得改回正式值，并同步文档。
