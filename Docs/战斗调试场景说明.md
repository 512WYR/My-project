# 战斗调试场景（Battle Lab）说明

## 入口

- 场景：`Assets/StageOne/Scenes/BattleLab.unity`。在 Unity 中直接打开后点 Play，或用菜单 **GameMake → Battle Lab → Open Battle Lab**。
- 校验：**GameMake → Battle Lab → Validate Setup** 检查场景、入口脚本与 `GameCatalog`。
- 重建：**GameMake → Battle Lab → Regenerate Scene** 会重新生成一个只有相机和 `BattleLab` 对象的场景。手工 YAML 若打不开，用这个菜单兜底。
- 该场景**不会**加入 Build Settings，正式入口是 `Assets/Scenes/mainScene.unity`。发布构建不会包含这个调试场景。

Battle Lab 与正式流程完全隔离：不引用 `StageOneApp`、`GothicHUD` 或 `Assembly-CSharp`，所有配置都克隆自 `GameCatalog`，不会写回 ScriptableObject 资产。

## 界面结构

顶部栏显示 Catalog、场次、回合、结果、当前行动者与 RNG State，并提供新建 Run、按配置开战、用当前 Run 再开一场。

四个标签页：

1. **配置**：内部再分四个子页，避免所有数据挤在一条长列表里。
   - **全局**：基础设置、战斗规则、部位规则（后两组可折叠）。
   - **队伍**：四个英雄槽各一张带颜色的卡片；点槽标题展开，内部按“基础属性 / 理智 / 部位与义肢 / 饰品与消耗品 / 技能列表”分组折叠。卡片标题直接显示 HP、攻击、速度、站位和理智。技能卡片折叠时仍显示描述，展开后可编辑描述。
   - **敌人**：四个敌人槽各一张卡片，按“基础属性 / 行为与阶段 / 技能列表”分组；标题显示 HP、攻击、速度、站位、宽度和行为。
   - **预设与数据**：一键预设、校验、应用开战与 JSON 导入导出。
2. **战斗**：状态、驱动、技能/换位/消耗品、场上角色（我方/敌方分开）、战斗内实时修改（按组折叠）。
3. **日志**：kind/Actor/Target/搜索过滤、只看当前场、自动滚底、复制与导出。
4. **工具**：不变量、查询纯函数、RNG 状态与快照、强制/锁定抽取、录制重放、Fuzz、bug bundle。

配置页顶部固定显示“当前配置”摘要（启用英雄数/敌人数、种子、规则来源）。所有分组标题都带 `[+] / [-]` 折叠标记，折叠时仍显示一行摘要，便于快速定位。

快捷键：`F5` 开战、`F6` 单步、`F7` 跑到玩家回合、`F8` 跑完整场、`F9` 跳过、`Esc` 清除选择。

## 调试种类

### 配置层

- 种子（十进制或 `0x` 十六进制）、玩家共享理智、满血开局、自动敌方与间隔。
- `CombatRules` 覆盖：概率强度、反馈系数、死亡概率、暴击倍率、理智步长、形态权重、失衡免疫回合、失衡位移必中回合、技能命中基准、追击/反击比例、部位规则。也可一键复制 Catalog 规则。
- 英雄槽：启用、角色来源、显式站位或自动站位、HP/Attack/Speed/Accuracy/Crit/Dodge/Defense、理智、只走理智技能、理智锁定待生效、四部位（完好/重伤/断肢）、义肢、8 件饰品、3 种消耗品数量、基础/低理智/高理智三份技能的全部字段。
- 敌人槽：来源（怪物优先，其次旧敌人）、`StartRank`、多站位宽度、全部属性、Behavior/Pattern、行动间隔/相位、守护减免、死亡回血、Immobile、三份技能列表。
- 预设：木桩、空敌（立即胜利）、空队（立即失败）、普通/精英/Boss 编队、尽量塞满全部怪物、全部饰品 + 消耗品 + 断肢装义肢。
- 校验会拒绝：非法种子、缺失角色、英雄多站位、站位重叠/越界、重复英雄 Id 之外的重复站位、重复/不存在的饰品、未断肢却装义肢、义肢部位不匹配、非法枚举。
- 同一角色占两个英雄槽时会自动给第二个 Id 加 `_2`/`_3` 后缀，避免 `BattleEngine` 的重复 Id 异常。

### 战斗层

- 技能列表会显示 `SkillDisabledReason` 与剩余次数；选择技能后选择合法目标（或确认无需目标），再执行。
- 换位、消耗品（消耗行动）、单步、跑到玩家回合、跑完整场、跳过当前行动、立即胜利/失败/撤退、用当前 Run 再开一场。
- 场上角色按“我方 / 敌方”分组显示 HP/死门、理智/形态、站位/宽度、流血、打断、失衡、位移必中到期回合、防御、守护、格挡、反击、追击、饰品、有效攻防命速、敌人意图与形态概率。
- 选中角色后可直接修改，编辑区按“生命与理智 / 基础属性 / 战斗状态与修正 / 快捷操作 / 部位与义肢 / 技能次数 / 饰品”分组折叠：HP/MaxHp、理智（直接赋值或走 `ChangeSanity`）、形态、站位、六项属性、全部战斗状态、技能次数、部位与义肢、饰品装备/卸下、击杀/复活/回满/清状态/重置技能次数/重置饰品状态/重建部位。

### 日志层

- kind：system、round、action、damage、heal、sanity、control、limb、death、deathdoor、bleed、form、move、guard、miss、dodge、settlement、debug。
- 按 Actor/Target 与文本过滤；日志页最多渲染最新 400 条，复制和导出使用完整列表。

### 工具层

- **不变量**：唯一 Id、HP/MaxHp、理智范围、站位与宽度、技能次数、饰品重复、部位上限、形态、守护者引用、当前行动者合法性、进行中/已结算的一致性、事件完整性、行动队列。
- **查询纯函数**：快照 RNG/Events/Current/Round/Outcome/行动队列，调用全部只读查询后确认没有副作用。
- **RNG**：查看/设置 State（十进制或 `0x`）、命名快照保存/恢复/删除、强制接下来 N 次抽取、锁定抽取、清除覆盖，以及“下一次 = 0 / ≈1”快捷按钮。
- **录制重放**：记录技能/换位/消耗品/敌方行动/跳过/强制抽取/锁定/清除；重放在独立 Session 中执行，首次分歧会报告步骤、RNG、事件数、Current、Round 或场次。手动改数值会使录制失效。
- **Fuzz**：场数、每场最大步数、种子、随机数值/装备/规则、失败即停；协程每场让出一帧，失败会保留配置、日志和状态文本。
- **导出**：配置 JSON、日志文本、重放 JSON、fuzz 报告、bug bundle。

## 关键语义与已知限制

- `DeathDoor = 我方 && 未死亡 && HP <= 0`。HP 为 0 不等于死亡；殉道路径也可能出现“已死亡但 HP > 0”。不变量按这个语义检查。
- `Form` 在每场开始和每个玩家回合重新抽取。开战前设置形态无效；战斗中设置只持续到该角色下一次回合。
- 开战饰品钩子只在 `BattleEngine` 构造时执行：跃动心脏标记、锈血入场扣血/额外次数、成瘾激活不会在战斗中补触发。要测这些请改配置后重开。
- 金丝苹果在装备时立即 +10 MaxHp，但不会自动补 HP；战斗中改 MaxHp 后可用“按当前 MaxHp 重建部位”让部位上限同步。
- 不提供战斗中增删敌人：引擎内部行动队列与 `Enemies` 列表不同步。请用击杀/复活，或在配置页替换后重开。
- 复活只设 `Dead=false; Hp=1`；开战时已死亡的角色不在结算名单里。
- 随机覆盖默认推进 xorshift State，所以覆盖后的序列与“未覆盖但消耗同样次数”一致；可关掉“推进 State”做窥视。`Roll(0)`/`Roll(1)` 本来就不抽随机，覆盖对它们无效。
- 配置用 `JsonUtility`：不支持 `Dictionary`、接口、多态、`Nullable`；枚举按整数；缺失字段回退默认。导入后会 Normalize + Validate，非法项会被拒绝。
- 战斗中直接修改字段会在下一次不变量检查中体现；所有入口都尽量 clamp，但极大/极小的自定义值仍可能产生引擎未覆盖的状态，建议改完立即“检查不变量”。

## 导出目录

`Application.persistentDataPath/BattleLab`。Windows 下通常是：

```
C:\Users\<用户名>\AppData\LocalLow\<公司名>\<产品名>\BattleLab
```

bug bundle 包含：`config.json`、`log.txt`、`state.txt`、`invariants.txt`、`meta.txt`，以及存在录制时的 `recording.json`。所有文件为 UTF-8 无 BOM。

## 代码位置

| 文件 | 职责 |
|---|---|
| `Assets/MainGame/Runtime/BattleLab/BattleLabConfig.cs` | 扁平配置 DTO、种子解析、Normalize |
| `BattleLabFactory.cs` | Catalog 解析、JSON 深克隆、站位/装备校验、构建 Run |
| `BattleLabSession.cs` | Run/Battle 生命周期、行动、实时修改、RNG 快照、录制钩子 |
| `BattleLabInvariants.cs` | 不变量与查询纯函数检查 |
| `BattleLabReplay.cs` | 录制步骤、独立会话重放、首个分歧 |
| `BattleLabFuzz.cs` | 随机配置与随机行动的批量测试 |
| `BattleLabJson.cs` | JSON/文本导出、bug bundle、状态描述 |
| `BattleLabLog.cs` | 战斗事件镜像与过滤 |
| `BattleLabApp.cs` + 四个 `*Page.cs` | IMGUI 入口与标签页 |
| `BattleLabUi.cs` / `BattleLabUiState.cs` | 中文字体、控件、瞬态 UI 状态 |
| `Assets/StageOne/Editor/BattleLabBuild.cs` | 打开/校验/重建场景，不修改 Build Settings |
| `Assets/StageOne/Tests/EditMode/BattleLab*Tests.cs` | 工厂、Session、随机/重放/Fuzz 的 EditMode 测试 |

Core 只增加了两个默认关闭的调试钩子：`BattleEngine.SkipCurrentTurn` 和 `RunRandom` 的强制/锁定抽取。正式流程没有调用者，默认随机序列逐位不变。

## 手工验收步骤

1. 打开 `BattleLab.unity`，Console 无错误、无 Missing Script，中文显示正常。
2. 默认队伍 vs 木桩：逐回合、改 HP、击杀敌人、结算，底部不变量始终正常。
3. Boss 编队：观察多站位、召唤替换、蒸汽机/操作者行为。
4. 给战士锈血、枪手穿肠弹、盾卫殉道锁链，重开验证入场钩子。
5. `DeathChance=1` + 金丝苹果验证理智归零死亡；`DeathChance=0` 验证存活。
6. 强制下一次随机为 0 / 0.999 验证命中、暴击、随机部位。
7. 录制若干步 → 重开 → 重放无分歧；手动改 HP 后录制标记失效。
8. 跑 20+ 场 Fuzz，界面不冻结，失败可导出 bug bundle。
9. 打开 `Assets/Scenes/mainScene.unity` 正常游玩一场战斗，确认正式流程无回归。
10. 在 Unity Test Runner 运行 EditMode 与 PlayMode 测试。
