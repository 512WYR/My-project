# 实施计划与当前进度

更新日期：2026年10月9日。设计依据：[游戏策划案 v0.3](游戏策划案_v0.3.md)。

## 目标与约定

在现有Unity 2022.3.62f3c1项目中制作Windows单机游戏：单章节、10层节点选择、最终首领、四职业、暗色中文界面与鼠标操作。包含站位战斗、双层理智、持续精神状态、肢体损伤、义肢、真相线索、图鉴与自动存档。跨局仅保留图鉴，当前冒险可以退出后继续。

保持内置渲染管线、现有输入方式和uGUI，不引入额外框架。规则使用独立C#类，内容使用可编辑数据资产，界面负责展示和操作。

最新分工：开发助手只负责代码和必要工程文件；项目负责人负责运行、测试、打包与验收。其他协作者的具体任务由负责人分配。每个阶段只实现本阶段及必要基础，交付后等待明确验收通过；问题先在当前阶段修复，不自动进入下一阶段。

- 已实现：统一概率算法、30/70区间激活、回合开始抽取技能形态、凝神与躁动的持续状态、角色个人理智延续。
- 已实现：锁定入战反馈名单，死亡成员使用最后有效理智，战后一次性反馈及结算显示。
- 已提供：开发验收入口、规则测试代码、场景测试代码和开发构建截图检查入口。
- 已验证：独立验证副本通过一次Unity编译并生成场景与默认数据。
- 未验证：自动测试结果、真实游戏流程、中文显示、1080p/720p布局和Windows构建。测试代码存在不代表测试已通过。
- 未实现：探索地图、肢体损伤、义肢、正式营地治疗、图鉴、磁盘存档和完整章节。

继续演练恢复存活成员生命，保留个人理智、持续精神状态与死亡；这是阶段一验收便利功能。关闭程序不保存演练进度，正式恢复与存档以后续阶段为准。

## 必须保持的规则

1. 角色理智小于30才能新触发原始技能与低理智精神状态；大于70才能新触发技术技能与高理智精神状态；30和70均无特殊触发资格。地图、事件与普通概率不使用此门槛。
2. 统一权重为 `b × g × exp(k × a × (S-50)/50)`，再归一化。初始k=1.5，技术/基础/原始基础权重为0.2/0.6/0.2。区间外特殊结果严格零权重，不能被装备或状态绕过。
3. 个人理智只在新局初始化，之后整局保留。已获得精神状态持续至治疗解除，不能因理智离开区间而自动消失，也不能擅自改变玩家指令。
4. 临时技能形态在角色回合开始时抽取，当回合固定，下回合重新检查。
5. 战后玩家理智变化为 `0.5 × 入战队员理智净变化平均值`。名单与分母入战锁定，死亡、撤退和读档不能漏算或重复。反馈之后才生成尚未确定的奖励。
6. HP首次归零进入濒死，再受伤进行死亡检定；回血脱离濒死，死亡成员本局不可恢复。
7. 后续存档必须同时保存随机序列状态与已经展示的决策内容，恢复不能重抽；冒险与图鉴独立保存。

## 用户运行与验收

打开 `Assets/StageOne/Scenes/StageOne.unity`，点击Play。F1查看帮助，F3打开开发验收工具，Esc关闭面板或取消目标选择。

验收清单见[第一阶段验收清单](第一阶段验收清单.md)。自动测试由负责人在Unity的Test Runner中分别运行EditMode和PlayMode。打包入口为 **GameMake → Build Stage One Windows**；该入口输出路径见编辑器构建代码，协作者可按实际环境调整。

本阶段收到明确“第一阶段验收通过”后才进入第二阶段。协作者可提前研究后续模块，但合入当前阶段运行链路须由负责人确认。
