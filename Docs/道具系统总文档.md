## 1. 一页速览

### 1.1 三件道具

| Id | 名称 | 枚举 | 一次使用效果 | 状态 |
|---|---|---|---|---|
| `con_sanity_lock` | 理智锁定药剂 | `ConsumableKind.SanityLock` | 目标本场战斗理智不增不减；战斗外使用则锁定下一场 | 可用 |
| `con_hp_restore` | 血量恢复药 | `ConsumableKind.HpRestore` | 目标恢复最大生命的 50%（向上取整、不超过上限） | 可用 |
| `con_surgery_kit` | 手术包 | `ConsumableKind.SurgeryKit` | 为任意未装义体的部位装载一件库存义体，消耗手术包与义体；无手术包时自由装载扣 8 点生命；补给站安装不扣生命 | 可用 |

### 1.2 六条硬规则

1. **成功才扣**：只有 `ConsumableSystem.Use` 返回 `true` 才从 `Run.Consumables` 移除一件。
2. **失败不动回合**：战斗中失败的使用既不扣库存，也不推进 `BattleEngine.Current`。
3. **战斗内消耗行动**：成功使用一件道具会结束当前角色的本次行动（`Advance()`）。
4. **战斗外立即可用**：路线、补给站、事件、电梯井、宝箱房都能打开面板，不消耗行动。
5. **查询不抽随机**：`UseBlockedReason`、`Count`、`Summary` 与界面刷新都不消耗 `Run.Random`。
6. **Core 不碰 Unity**：`Assets/StageOne/Core` 不引用 `UnityEngine`，规则可在纯 .NET 下编译测试。

## 2. 道具解释

### 2.1 理智锁定药剂

对一名存活角色使用，按使用时机分两种结算：

| 阶段 | 行为 | 字段 |
|---|---|---|
| 战斗外使用 | 预置「下一场锁定」，当前理智不变 | `SanityLockPending = true` |
| 下一场战斗开始 | 存活角色把预置转成本场锁定 | `SanityLocked = true`，`Pending = false` |
| 战斗中直接使用 | 立刻挂上本场锁定，结束本次行动 | `SanityLocked = true` |
| 锁定期间理智变化 | 增减都被拒绝，只写一条战斗日志 | `BattleEngine.ChangeSanity` 提前返回 |
| 战斗结束 | 无论胜利、失败还是撤退，两层标记一起清空 | `BattleEngine.Finish` |

边界约定：

- **不能叠加**：目标已有 `SanityLocked` 或 `SanityLockPending` 时再次使用会被拒绝（提示「理智已经被锁定。」），库存不扣。
- **只管角色理智**：锁定保护 `ActorState.Sanity`。玩家的汇总理智 `RunState.PlayerSanity` 是独立字段，战后反馈仍正常计算。
- **战斗外不生效**：预置锁定只在战斗开始时成熟；战斗外的事件、祭坛、补给站仍可直接改角色理智。
- **不掷死亡检定**：`ChangeSanity` 在锁定判断处提前返回，因此金丝苹果「理智归零直接死亡」的检定也不会触发。
- **不抽随机**：锁定判断在抽取之前返回，随机序列与没有该道具时一致。

### 2.2 血量恢复药

- 恢复量 = `ceil(最大生命 × 50%)`，最后夹到 `MaxHp`。
- 最大生命取 `Definition.MaxHp`，所以金丝苹果等入场加成会一起计入。
- 当前生命已满 → 拒绝，提示「生命已满。」，库存不扣。
- 阵亡角色 → 拒绝，提示「已经阵亡。」，不能复活。
- 濒死（`Hp == 0` 但 `Dead == false`）→ 可以治疗，并且会解除 `DeathDoor`。
- 治疗调用 `Exploration.Heal`，属于道具结算而不是治疗技能，因此：
  - 不吃献血针筒的 100% 治疗加成；
  - 不触发针筒「随机一名队友损失 20% 最大生命」的代价；
  - 不消耗随机数。

### 2.3 手术包

- `Kind = SurgeryKit`，`Implemented = true`。它在「安装义体」这件事上替代补给站：**消耗一个手术包 + 一件库存义体**，把义体装到对应角色的任意未装义体的部位上。
- 入口在角色面板 → 选择肢体 → 义体列表 →「消耗手术包装载」。没有手术包时按钮变为「自由装载 · 生命 -8」，**不消耗手术包但失去 8 点生命**。补给站「部位与义肢 → 选择义体」仍按原规则消耗矿石，不需要手术包且不扣生命。
- 安装条件复用 `LimbSystem.InstallBlockedReason`：任意未装义体的部位可装，已装义体的部位不可替换，专属义体必须角色匹配。失败时手术包与义体都不扣除。
- 成功时先 `LimbSystem.Install`，再各移除一件手术包与义体（`ConsumableSystem.UseSurgeryKit`）。
- 战斗外安装立即生效、不消耗行动；战斗中安装消耗当前角色本次行动、关闭角色面板，并走与药剂相同的 `ContinueEnemies` 流程（`BattleEngine.EndTurnAfterSurgery`）。
- 通用入口 `ConsumableSystem.Use` / `BattleEngine.UseConsumable` 没有「选哪件义体」的目标，因此会拒绝并提示「请在角色面板的义体列表中选择要安装的义体。」；库存与行动都不变。
- 调试台的「使用」按钮因此对手术包保持禁用；调试安装仍使用调试台的四个「安装·部位」按钮。

### 2.4 通用使用规则

- **目标必须存活**：角色面板一次显示一名角色，可切换到任一队员；阵亡角色仍可查看，但药剂按钮会禁用。
- **每件道具独立占格**：同一件道具持有多份时，库存里就是多条记录；使用哪一条只影响那一条。
- **使用后移除**：`RemoveAt(stockIndex)` 发生在效果结算之后、返回之前。
- **战斗外保持面板**：使用成功后刷新但不关闭，方便连续使用；战斗中成功后关闭角色面板并继续结算敌人行动。
- **面板互斥**：角色面板打开时调试台不能打开，反过来也一样；`Esc` 优先关闭角色面板。帮助页、内置验收页与旧的饰品/道具弹窗都已移除。

## 3. 架构与数据流

### 3.1 分层

```
输入 / UI（全部来自预制体）
  CharacterPanelView（Canvas 45，药剂区）
  IndustrialDebugConsole（Canvas 80，物品与饰品页）
  GothicBattleHudController（Canvas 10，快捷物品槽已隐藏）
        │  只发命令，不写规则
        ▼
StageOneApp（运行态命令层）
  角色面板开关、门禁、战斗/非战斗分支、调试发放
        │
        ├── 战斗内 ──► BattleEngine.UseConsumable
        │                 └── ConsumableSystem.Use(inBattle: true)
        │                 └── Log / CheckEnd / Advance
        └── 战斗外 ──► ConsumableSystem.Use(inBattle: false)
        ▼
Ruin.Core（纯 C#）
  ConsumableModel / ConsumableSystem / Models / BattleEngine / Exploration
        ▼
RunState
  List<ConsumableSpec> Consumables
  ActorState.SanityLocked / SanityLockPending
```

### 3.2 使用流程

```
点击角色面板的药剂按钮
  → App.CharacterUsePotion(kind)
      → 在库存中按 Kind 找到第一条记录，取其下标
      → CanManageCharacter / CharacterPotionBlockedReason 先行校验
      → 战斗中：Battle.UseConsumable(stockIndex, heroId)
          → 校验战斗仍在进行、当前是我方行动、库存下标合法、目标存在
          → ConsumableSystem.Use(...)
              → UseBlockedReason 再校验一次
              → RemoveAt
              → 结算（Heal / 写锁定字段）
          → 失败：返回 false，库存与回合不变
          → 成功：Log → CheckEnd → Advance
      → 战斗外：ConsumableSystem.Use(...)
          → 成功：刷新并保持面板打开
```

### 3.3 三条数据不变量

1. `Run.Consumables` 里的元素永远来自 `ConsumableSystem.Defaults` 的 `Clone`，不会把只读内容表实例直接塞进存档。
2. `SanityLocked` 与 `SanityLockPending` 都只由道具或战斗生命周期写入；战斗结算时两者必然同时为 `false`。
3. 任何校验、按钮禁用状态、库存计数、说明文本都不得调用 `Run.Random`。

#### 禁用判定的顺序

[ConsumableSystem.cs:77-93](../Assets/StageOne/Core/ConsumableSystem.cs#L77-L93)

| 顺序 | 条件 | 返回值 |
|---|---|---|
| 1 | `item == null` | 「请选择一件道具。」 |
| 2 | `!Implemented` | 「功能待定。」 |
| 3 | `Kind == SurgeryKit` | 「请在角色面板的义体列表中选择要安装的义体。」 |
| 4 | `hero == null` | 「请选择一名队员。」 |
| 5 | `hero.Dead` | 「已经阵亡。」 |
| 6 | 锁定类且 `SanityLocked / SanityLockPending` | 「理智已经被锁定。」 |
| 7 | 回血类且 `Hp >= MaxHp` | 「生命已满。」 |
| 8 | 其余情况 | `null`（可以使用） |

顺序很重要：未实现、手术包与阵亡的提示优先于数值判断，避免在满血角色上显示「生命已满」这种误导信息。

#### `Use` 的执行顺序

[ConsumableSystem.cs:97-131](../Assets/StageOne/Core/ConsumableSystem.cs#L97-L131)

1. 校验 `run`、库存列表与下标；
2. 取 `item` 并调用 `UseBlockedReason`；
3. 校验通过后才 `RemoveAt(stockIndex)`；
4. 按 `Kind` 结算：
   - `HpRestore` → `Exploration.Heal(hero, HealPercent)`，返回实际恢复量；
   - `SanityLock` → 战斗内写 `SanityLocked`，战斗外写 `SanityLockPending`；
   - `default` → 插回原位并返回 `false`（防御未来新增但未实现的分支）；
5. 写入中文 `note` 并返回 `true`。

#### 治疗依赖 `Exploration.Heal`

[NodeContent.cs:93-100](../Assets/StageOne/Core/NodeContent.cs#L93-L100)

```csharp
public static int Heal(ActorState hero, int percent)
{
    if (hero == null || hero.Dead || percent <= 0) return 0;
    int amount = Math.Max(1, (int)Math.Ceiling(hero.Definition.MaxHp * percent / 100.0 - 1e-9));
    int before = hero.Hp;
    hero.Hp = Math.Min(hero.Definition.MaxHp, hero.Hp + amount);
    return hero.Hp - before;
}
```

- `Ceiling` 保证 20.5 变 21；
- `-1e-9` 消除浮点误差（例如 20.000000000000004 不应向上取成 21）；
- `Math.Min` 夹住上限；
- 阵亡直接返回 0，因此道具不会复活角色；
- 该路径不读取针筒，也没有随机调用。

#### 4.4.2 战斗内使用入口 `UseConsumable`

[BattleEngine.cs:270-286](../Assets/StageOne/Core/BattleEngine.cs#L270-L286)

```csharp
public bool UseConsumable(int stockIndex, string targetId, out string note)
{
    note = null;
    if (Outcome != BattleOutcome.Active) { note = "战斗已经结束。"; return false; }
    if (Current == null || !Current.Player) { note = "现在不是我方行动。"; return false; }
    if (Run.Consumables == null || stockIndex < 0 || stockIndex >= Run.Consumables.Count)
    { note = "请选择库存中的道具。"; return false; }
    var target = Run.Heroes.FirstOrDefault(a => a != null && a.Id == targetId);
    if (target == null) { note = "请选择一名存活队员。"; return false; }
    var item = Run.Consumables[stockIndex];
    if (!ConsumableSystem.Use(Run, target, stockIndex, true, out note)) return false;
    Log(note, item.Kind == ConsumableKind.HpRestore ? "heal" : "sanity", Current.Id, target.Id);
    if (!CheckEnd()) Advance();
    return true;
}
```

要点：

- 四层前置校验都在 `ConsumableSystem.Use` 之前，任何一层失败都不会扣库存；
- 日志来源角色是 `Current.Id`，目标是 `target.Id`；
- 使用后先 `CheckEnd()`：如果这一下让战斗结束，就不再推进回合；
- 否则 `Advance()` 消耗当前行动，进入下一个行动者；
- 失败的 `ConsumableSystem.Use` 直接返回，既不 `Log` 也不 `Advance`。

#### 4.5.2 开关与门禁

`CharacterPageAvailable` 的隐含条件：

| 条件 | 原因 |
|---|---|
| `Run != null` | 必须有进行中的演练 |
| `!DebugOverlayOpen` | 调试台打开时角色面板让位（`CharacterPanelView` 会自动关面板） |

#### 4.5.3 使用分支

[CharacterPanelCommands.cs:33-52](../Assets/MainGame/Runtime/CharacterPanelCommands.cs#L33-L52)

```csharp
public void CharacterUsePotion(ConsumableKind kind)
{
    string blocked = CharacterPotionBlockedReason(kind);
    if (blocked != null) { Hint = blocked; Refresh(); return; }
    int index = Run.Consumables.FindIndex(c => c != null && c.Kind == kind);
    var hero = CharacterHero;
    if (!AwaitingNode)
    {
        int from = Battle.Events.Count;
        if (!Battle.UseConsumable(index, hero.Id, out string battleNote))
        { Hint = battleNote; Refresh(); return; }
        CharacterPanelOpen = false; CharacterHeroId = null; ClearPending(); Hint = battleNote;
        StartCoroutine(ContinueEnemies(from));
    }
    else
    {
        ConsumableSystem.Use(Run, hero, index, false, out string note);
        Hint = note; Refresh();
    }
}
```

- 按 `Kind` 取库存中第一条记录，因此同种药剂持有多份时总是先用最早的一条；另一种药剂走各自的按钮，互不影响。
- 战斗内：记录 `from` 作为敌人播报起点；成功后关面板并交给 `ContinueEnemies`；
- 战斗外：使用后保持角色面板打开，只刷新；
- 失败路径统一写 `Hint` 并刷新，不改库存。
- `CharacterPotionBlockedReason` 与按钮的禁用状态同源：角色不可管理时返回「等待我方行动后可操作」，空库存返回「库存不足」，其余交给 `ConsumableSystem.UseBlockedReason`。

## 6. 约束与不变量

| 约束 | 原因 |
|---|---|
| `Assets/StageOne/Core` 不引用 `UnityEngine` | 规则可在纯 .NET 下编译与独立验证 |

- 查询不改变 `Random.State`。

## 8. 排查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 点击头像打不开角色面板 | 不在路线页、战斗已结束，或调试台正打开 | 检查 `CharacterPageAvailable`；关闭调试台 |
| 药剂按钮是灰的 | `Busy`、敌人行动中、角色阵亡、满血/已锁定或库存不足 | 按钮下方会显示 `CharacterPotionBlockedReason` 的原因 |
| HUD 快捷物品槽不见了 | 这是预期行为 | 控制器在 `Bind()` 中隐藏 `Items - 快捷物品`；药剂走角色面板 |
| 角色面板没显示锁定状态 | 预制体面板只显示库存与可用性 | 用调试台「物品与饰品」页确认 `SanityLocked / SanityLockPending` |
| 用了道具但没扣库存 | 走的是失败路径；或直接调用了 UI 而没有走 `Use` | 统一通过 `StageOneApp.CharacterUsePotion`、`DebugUseConsumable` 或 `ConsumableSystem.Use` |
| 战斗中用道具后还能再行动 | 调用方没有走 `BattleEngine.UseConsumable`，或重复调用了同一回合 | 检查是否绕过 App 命令 |
| 锁定没撑到战斗结束 | `Finish` 被提前调用或被外部清字段 | 搜索所有写 `SanityLocked` 的位置，只允许道具与战斗生命周期 |
| 下一场还被锁 | `Finish` 没走到（例如调试直接重开演练） | 确认结算路径；`NewRun` 会重建 `ActorState` |
| 角色面板能直接装上义体、手术包没扣 | 调用了 `LimbSystem.Install` 而没有走 `ConsumableSystem.UseSurgeryKit` | 统一走 `StageOneApp.CharacterInstallProsthetic` |
| 持有手术包却提示需要手术包 | 手术包被 `Implemented = false`、库存种类对不上，或界面读取了旧的存档库存 | 检查 `ConsumableKind.SurgeryKit` 与 `Count` |
| 调整 `HealPercent` 后测试失败 | EditMode 测试写死了旧数值 | 同步更新测试期望 |
| 冒烟报缺字 | 新文案含字体图集没有的汉字 | 在烟雾测试的探测字符串中补上，或换用已有字 |
