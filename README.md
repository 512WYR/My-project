## 已实现范围

四名角色（战士/盾卫/枪手/奶妈）、站位与速度回合、技能目标选择、区间概率、技能形态、攻击预告、格挡、守护、反击、追击、失衡、打断、拖拽、流血、治疗、濒死、死亡及战后理智反馈。**每回合的行动只有当前形态的技能加一个换位**，没有职业系统、防御、稳定心神、直视深渊与撤退；全队阵亡直接结束本局。

第一阶段是可重复的战斗演练：继续演练会恢复存活队员生命，保留个人理智，死亡队员不复活。三层路线、增益房、补给站、事件与祭坛、肢体与义肢已提前落地，宝箱房已上路但奖励未定。尚无永久图鉴和磁盘存档；这些属于后续阶段。

## 操作

- 点击技能，再点击高亮目标。点击角色查看理智、技能概率或敌人预告。
- F1：操作说明。F3：开发验收工具。Esc：关闭面板或取消目标选择。
- F3提供理智15、50、85的新测试队伍，以及濒死和反馈负2.5样例。
- 当前回合技能不因中途调整理智重抽，下一角色回合开始才更新。

## 可编辑内容

数据在 `Assets/StageOne/Resources/StageOne`：

- `GameCatalog.asset`：队伍、敌人及全局概率强度、反馈系数和死亡概率。
- `Characters`：角色与敌人的生命、速度、战斗属性及**三份技能列表**（常态 / 低理智 / 高理智特殊技能）。
- `Skills`：伤害、作用范围、治疗、次数、流血与打断。

站位掩码采用位置1至4对应1、2、4、8，例如3表示位置1和2，15表示全部位置。完整的字段说明、敌人编队编辑方式和 Battle Lab 调参固化流程见 [数据修改指南](Docs/数据修改指南.md)。

## 结构与验证

`Core`是无Unity依赖的规则层；`Runtime`是数据适配和uGUI表现；`Editor`负责生成入口与构建；`Tests`包含规则与场景测试。

通过Unity Test Runner运行EditMode及PlayMode测试。菜单 **GameMake → Build Stage One Windows** 生成开发试玩版至工作区 `交付/阶段一/Windows试玩版`。

开发试玩支持 `--stage1-smoke --qa-out <输出目录>`，运行UI流程与截图检查并自动退出。该入口与F3工具均不包含在非开发发行构建中。

完成本阶段后暂停，等待用户验收通过，再进入第二阶段。
