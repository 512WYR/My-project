# 实施计划与当前进度

更新日期：2026年10月13日。设计依据：[游戏策划案 v0.3](游戏策划案_v0.3.md)。

## 目标与约定

在现有Unity 2022.3.62f3c1项目中制作Windows单机游戏：单章节、三层节点路线、最终首领、四名角色、暗色中文界面与鼠标操作。包含站位战斗、双层理智、肢体损伤、义肢、真相线索、图鉴与自动存档。跨局仅保留图鉴，当前冒险可以退出后继续。

保持内置渲染管线、现有输入方式和uGUI，不引入额外框架。规则使用独立C#类，内容使用可编辑数据资产，界面负责展示和操作。

最新分工：开发助手只负责代码和必要工程文件；项目负责人负责运行、测试、打包与验收。其他协作者的具体任务由负责人分配。每个阶段只实现本阶段及必要基础，交付后等待明确验收通过；问题先在当前阶段修复，不自动进入下一阶段。

## 必须保持的规则

1. 角色理智小于30才能新触发原始技能；大于70才能新触发技术技能；30和70均无特殊触发资格。地图、事件与普通概率不使用此门槛。
2. 统一权重为 `b × g × exp(k × a × (S-50)/50)`，再归一化。初始k=1.5，技术/基础/原始基础权重为0.2/0.6/0.2。区间外特殊结果严格零权重，不能被装备或状态绕过。
3. 个人理智只在新局初始化，之后整局保留。
4. 临时技能形态在角色回合开始时抽取，当回合固定，下回合重新检查。形态决定该回合**用哪一份技能列表**：常态是常规四技能，高理智是常规四技能加特殊技能，低理智只剩变化后的那一个技能。
5. 战后玩家理智变化为 `0.5 × 入战队员理智净变化平均值`。名单与分母入战锁定，死亡与读档不能漏算或重复。反馈之后才生成尚未确定的奖励。
6. HP首次归零进入濒死，再受伤进行死亡检定；回血脱离濒死，死亡成员本局不可恢复。
7. 角色战斗属性固定在角色定义中，不随理智变化。有效命中率 = 角色命中率 +（技能精度 − 0.9）；命中率、暴击率与闪避为固定概率，不叠加统一算法的理智倾向；闪避为0时跳过判定且不消耗随机序列。
8. 技能伤害与治疗 = 基础攻击力 × 技能倍率，暴击乘1.5；受伤先按目标防御比例减伤，再叠加防御姿态的减半，向上取整且不低于1；流血无视防御属性与防御姿态。防御姿态的减半逻辑仍在引擎里，但已经没有任何行动能设置它。敌方伤害 = 敌方基础攻击力 × 形态倍率，预告与实际结算共用同一函数。
9. 后续存档必须同时保存随机序列状态与已经展示的决策内容，恢复不能重抽；冒险与图鉴独立保存。
10. 房间类型与候选数量读取玩家理智，使用普通结果连续变化，不使用30/70门槛；房间类型的强度k为1.0，低理智的危险偏向收敛（精英加祭坛合计从理智85的约13.1%升到理智15的约39.8%；祭坛与宝箱都不随理智倾斜，看到就选时一局各约进入3次）。候选数量在此基础上再乘一个倾向强度 `MapBranchAffinity = 1.5`，期望候选数在理智20/50/80 为 1.50 / 2.00 / 2.50，理智50 时「2个」是最常见的一档。路线固定为三层，每层首节点固定（第1层初始增益房，第2、3层补给站）、末节点固定（第1、2层电梯井，第3层首领），每层恰有两个固定位置；可抽位置上只出现普通战斗、精英战斗、祭坛房间、事件房间与宝箱房五种，权重为0的类型一次都不出现；同一个位置上的候选不重复同一种房间，事件房间除外。已经展示的位置由 `MapGenerator.Advance` 幂等保存，重复生成不重抽、不消耗随机序列；调试跳步时中间被跳过的位置仍按顺序补齐，随机序列与逐格走完一致。抽取次数为显式契约：固定位置0次，可抽位置为「候选数量+1」次。进入下一层不自动整备生命。
11. 部位血量只减不增：一次部位攻击重伤、两次断肢；断肢削弱替换重伤削弱而不叠加；四个部位断肢都不致死、不禁止技能与换位。每次敌方攻击命中并造成实际生命伤害后，随机一个未断部位承受 `ceil(实际伤害 × LimbDamageRatio)`（默认 0.5，至少 1）；一次命中每个目标最多一个部位，多目标技能对每个命中英雄分别判定。未命中、闪避、格挡、部位全断与金丝苹果锁定不结算也不抽取；`Intent` 写明部位磨损且本身不消耗随机序列。断肢**不可修复**，只能安装义肢；义肢只恢复基础功能，且随部位再次被打断。修复与安装只在补给站内进行，补给站在每层起点固定出现，离开即继续前进。
12. 事件内容在同局内去重：进房时抽一次并写入 `MapState.EventHistory`；优先未出现内容，池耗尽后选最久未见，重复继续追加。EVT-005/EVT-006 带 `Healing` 标记，只有 `RunState.Battles >= 1` 才进入事件池，首战前不会出现。调试台强制事件绕过门槛且不写历史；祭坛池只有 EVT-008，可重复。

## 用户运行与验收

打开 `Assets/Scenes/mainScene.unity`，点击Play。这是唯一正式入口，全部页面来自预制体。开局先选一个全队增益，之后逐格从1~3个候选房间中选一个前进；点击队伍头像打开角色面板，Esc 关闭面板或取消目标选择。没有 F1 / F3 / I 快捷键。

屏幕上的「调试台」是唯一的开发验收入口，页签依次为概览、队伍、战斗、地图与房间、事件、部位与义肢、物品与饰品、规则与目录、日志：

- 「战斗」页有「整备全队生命」「濒死演练」「反馈样例（−2.5）」「直接胜利」「撤退结算」。
- 「地图与房间」页有「跳到本层末端」「跳到首领层」，以及「补给站 / 事件房 / 祭坛房 / 宝箱房 / 电梯井 / 普通战斗 / 精英战斗 / 首领战 / 初始增益」九个强制房间按钮。
- 「部位与义肢」页有「击伤 / 断肢」，义肢在「物品与饰品」页发放。

**事件验收**在「事件」页：十条事件各有一个按钮，按下就把当前位置换成那一条并直接走进去，不必靠运气抽到；页内还有「直接打赢」与「撤退结算」，用来对照撤退不发奖励。四条分支藏在理智区间里（EVT-H001、EVT-L001，以及 EVT-004 的「全部喝下」、EVT-005/006 的低理智分支），验收时先在「概览」页把玩家理智设为 15 / 85，再点「新开演练 · 沿用当前玩家理智」——事件闸门与地图读的正是玩家理智。Esc 关闭调试台。

验收清单见[第一阶段验收清单](第一阶段验收清单.md)。自动测试由负责人在Unity的Test Runner中分别运行EditMode和PlayMode。打包入口为 **GameMake → Build Stage One Windows**；该入口输出路径见编辑器构建代码，协作者可按实际环境调整。

本阶段收到明确“第一阶段验收通过”后才进入第二阶段。协作者可提前研究后续模块，但合入当前阶段运行链路须由负责人确认。
